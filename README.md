# ГолосУЗИ (UZD Voce) · Приказ МЗ РФ № 1130н

Офлайн-приложение для врачей УЗ-диагностики: голосовая диктовка → авторазбор по полям →
протокол скринингового УЗИ (I, II, III триместр) → печать / PDF / DOC / отправка.

Дополнительно реализовано **лицензирование**: бесплатный пробный период 3 дня и платные
ключи на срок (например, 1 год), привязанные к устройствам клиента. Проверка ключа
происходит **офлайн** — интернет нужен только чтобы получить ключ по почте.

**Демо (GitHub Pages):** https://koksasa.github.io/UZDvoce/

## Быстрый старт

```bash
npm install          # установить инструменты сборки
npm run keys:init    # ОДИН РАЗ: создать пару ключей подписи
npm run build        # собрать релиз в docs/
npm test             # автотесты: запуск приложения, триал, активация, блокировка экспорта
npm run serve        # локальная проверка → http://localhost:8080
```

> ⚠️ `npm run keys:init` создаёт `keys/private.pem`. **Сразу сделайте резервную копию.**
> Если потеряете файл — не сможете выпускать ключи. Если он утечёт — любой сможет
> подделать лицензию. В репозиторий он не попадает (см. `.gitignore`).

## Как выдать ключ клиенту (рабочий процесс)

### Быстрый способ — мастер (рекомендуется)

Дважды щёлкните **`Выдать ключ.bat`** в папке проекта — откроется мастер,
который спросит ID устройства, срок и ФИО и сразу выдаст готовый ключ:

```
  1) ID устройства клиента (XXXX-XXXX-XXXX-XXXX): PB27-S844-AQNB-JS9D
  2) Второе устройство, ПК+телефон (Enter — нет):
  3) Срок действия:  [1] 3 дня  [2] 6 мес  [3] 1 год  [4] 2 года  [5] свой
  4) ФИО владельца: Иванова М.П.
```

Ключ автоматически **копируется в буфер обмена** и **сохраняется** в `keys/issued/`.
Тот же мастер из терминала: `npm run key:wizard`.

### Пошагово

1. **Клиент** открывает сайт, нажимает на чип статуса в шапке → «Активация».
   Копирует **ID устройства** (например, `PB27-S844-AQNB-JS9D`) и присылает вам вместе с ФИО.
   *Для второго устройства (ПК + телефон) — пусть пришлёт оба ID.*

2. **Вы** выпускаете ключ — либо мастером выше, либо командой:

   ```bash
   # 1 устройство, 1 год
   npm run key -- --device PB27-S844-AQNB-JS9D --months 12 --name "Иванова М.П."

   # 2 устройства (ПК + телефон) в одной лицензии
   npm run key -- --device PB27-S844-AQNB-JS9D --device2 WXYZ-1234-5678-9ABC --months 12 --name "Иванова М.П."

   # пробный ключ на 3 дня
   npm run key -- --device PB27-S844-AQNB-JS9D --days 3 --type trial
   ```

   Генератор выведет **готовый текст письма** — скопируйте и отправьте клиенту.

3. **Клиент** вставляет ключ в окно активации → «Активировать». Готово, интернет больше не нужен.

Проверить любой ключ можно так:

```bash
node tools/keygen.mjs verify --token "UZI1-..." --device PB27-S844-AQNB-JS9D
```

**Сайт при выдаче ключей пересобирать и перезаливать не нужно.** Ключ выдаётся клиенту
напрямую, приложение проверяет его само.

## Публикация на GitHub Pages

Репозиторий: **https://github.com/KoksaSa/UZDvoce** · Сайт: **https://koksasa.github.io/UZDvoce/**

1. Репозиторий **публичный** (на бесплатном тарифе Pages работает только с публичными).

2. Соберите релиз и проверьте, что приватный ключ не попадёт в коммит:

   ```bash
   npm run build
   git init
   git add .
   git status            # в списке НЕ должно быть keys/private.pem
   git commit -m "ГолосУЗИ (UZD Voce)"
   git branch -M main
   git remote add origin https://github.com/KoksaSa/UZDvoce.git
   git push -u origin main
   ```

3. В репозитории: **Settings → Pages → Source: Deploy from a branch → Branch: `main` → Folder: `/docs` → Save.**

4. Через минуту сайт будет доступен по адресу
   **https://koksasa.github.io/UZDvoce/**.

Приложение использует относительные пути (`./sw.js`, `./vendor/…`), поэтому корректно
работает и в подпапке репозитория. `.nojekyll` уже добавлен сборкой.

### Обновление версии

После любых правок `UZD.html` или `src/`:

```bash
npm run build && npm test
git add docs && git commit -m "обновление" && git push
```

> **Важно:** не удаляйте и не заменяйте `keys/private.pem` при обновлениях — иначе ранее
> выданные ключи перестанут проверяться. Меняйте ключ подписи только осознанно.

## Что защищено, а что нет (честно)

| Защищено | Как |
|---|---|
| Ключ нельзя подделать | Подпись ECDSA P-256; приватный ключ есть только у вас |
| Ключ не работает на чужом устройстве | ID устройства входит в подписанные данные |
| Триал сбрасывается не очисткой данных | Метка первого запуска хранится в 4 хранилищах (IndexedDB, localStorage, cookie, Cache API) |
| Перевод системных часов назад | Сверка с максимальным «виденным» временем |
| Исходники сложно прочитать | Обфускация модуля лицензии (`javascript-obfuscator`), минификация |

| Не защищено (и не может быть в браузере) | Почему |
|---|---|
| Полная невозможность обойти проверку | Код исполняется на устройстве клиента; при большом желании его можно изменить |
| Триал при полной очистке данных браузера | Офлайн-приложение не может отличить сброс от нового устройства |
| Запрет переноса ключа при копировании профиля браузера | ID хранится в браузере, а не в «железе» |

Это стандартный уровень защиты для офлайн-веб-приложения. Он отсекает обычных
пользователей (они просто покупают), но не остановит целенаправленный взлом.
Если потребуется жёстче — можно добавить серверную проверку (Cloudflare Workers + KV
бесплатно), тогда появятся отзыв ключей и учёт триала по ID устройства.

## Технические детали лицензии

- **Формат ключа:** `UZI1-<base64url(payload)>.<base64url(ECDSA-подпись)>`
- **payload:** `{ v, t: paid|trial, d: [deviceId…], exp, iat, n: ФИО, s: соль }`
- **Устройств на ключ:** до 2 (ПК + телефон)
- **Проверка:** `crypto.subtle` (WebCrypto), ECDSA P-256, SHA-256, офлайн
- **Хранение:** IndexedDB + localStorage + cookie + Cache API
- **Требование:** активация возможна только по `https` (WebCrypto недоступен на `file://`);
  в пробном режиме приложение работает и без `https`.
- **Где блокируется экспорт без лицензии:** PDF, DOC, копирование, отправка, печать,
  сохранение в историю. Заполнение протокола и просмотр не ограничиваются — врач не теряет
  уже введённые данные.

## Лицензия на код (важно при создании репозитория)

GitHub Pages работает **с любой лицензией и вообще без неё** — лицензия на хостинг не влияет.

При создании репозитория GitHub предложит шаблон лицензии (MIT, Apache, GPL…). Для
**платного продукта их выбирать нельзя**: они разрешают любому свободно использовать,
изменять и распространять код, в том числе продавать его.

Правильно:

- в выпадающем списке «Choose a license» выбрать **None**;
- в проект уже добавлен файл [`LICENSE`](LICENSE) с проприетарным текстом
  («все права защищены, коммерческое использование запрещено»).

Помните: на бесплатном тарифе GitHub Pages репозиторий обязан быть **публичным**, то есть
исходный код виден. Лицензия определяет, что с ним разрешено делать, а обфускация модуля
лицензии затрудняет копирование. Это максимум, что даёт GitHub Pages для закрытого кода;
для полностью приватного репозитория нужен GitHub Pro или другой хостинг
(Cloudflare Pages/Netlify — бесплатно из приватного репозитория).
